# Historical PUBLIC runtime profile guard

Historical public replay must enforce the architecture, kernel and CPU recorded
in its qualified execution profile. The immutable public runner previously
checked software and measurement bindings but did not call the generic runtime
comparison already installed in the same image. This is a trusted command
wrapper repair; it changes no image, historical benchmark, Lean release,
nanoda/component pin, measurement limit, State event or profile identity.

The existing protected start request now requires the complete qualified
execution_profile. Missing profiles are rejected; no unguarded compatibility
fallback exists. The Worker validates its closed fields and Unicode, rejects an
unavailable CPU, and recomputes SHA256 over the domain
`lean-eval-replay-execution-profile-v1`, a NUL, and sorted compact UTF-8 JSON
without ASCII escaping. It compares the digest and image with the reviewed
configuration before claiming an active binding or looking up a sandbox. It
writes exactly those hashed canonical JSON bytes to one fixed expectation path.
The existing source-free cleanup reservation route remains unchanged.

The fixed background command begins with `/usr/bin/python3 -I -S -B`. Its
constant Python imports the installed immutable replay-authoritative module
under a non-main name and calls platform_evidence/validate_runtime_profile.
The comparison runs before base64 decoding or the public runner can extract
source. The prefix contains no request-controlled command or interpolation.
It writes no stdout on success, so the existing runner-verdict schema is
unchanged. A mismatch exits42 with a fixed stderr line; an internal guard error
exits43 with a separate fixed line. Only failed status, the matching distinctive
exit code, empty stdout and exact stderr together produce the typed detail.
All other failures retain the generic orchestration classification. Destruction
must still be confirmed before terminal failure; no mismatch automatically
marks a profile permanently unavailable or fabricates a checker outcome.

The installed Sandbox SDK0.12.7 exposes command and exitCode. Start duplicates
and status reads require the exact guarded public command before accepting a
live process or preparing a receipt. A status transition between SDK snapshots
may leave an absent exitCode and a generic detail; this cannot falsely attest a
runtime match. Generic/private process behavior is unchanged. Stored receipts
retain the existing schema and remain historical evidence; the wrapper cannot
retroactively attest an old receipt or process.

The profile's330-minute evaluator limit and335-minute outer process timeout
remain unchanged. The small guard runs inside the existing outer process
window. It checks actual runtime rather than assuming a container pins its
host kernel. All35 committed profile digests are parity-tested; the remaining
thirteen profiles use two immutable image-source commits, both with identical
reviewed platform comparison functions and standard-library-only module load.
The immutable Cloudflare0.12.7-python base image history confirms its
/usr/bin/python3 alternative. These source/image-history checks do not replace
staging execution on the actual Cloudflare platform.

Production rollout requires the old pilot to finish and be ingested completely
by the controller revision that started it. Confirm no historical public attempt
is running and use fresh nonces under the new protected baseline. Never poll or
relabel an old pilot nonce through this Worker to claim it was guarded. Run a
separately reviewed bounded staging test for each distinct immutable image-source
family: observe runtime through the existing staging-acceptance route, prove a
matching tiny public replay, then a staging-only altered expected profile must
fail before source decoding and confirm destruction. This is a compatibility
check of unchanged images, not new image qualification or a State campaign.

Actual host values are currently unobserved by this change. If staging finds a
mismatch, stop and report truthful evidence; do not substitute expected values
or rewrite frozen profiles. Existing State replacement requires a genuine
unavailable or allowed nonretryable profile-failure disposition and new reviewed
qualification. A queued or running task cannot be silently reconfigured. The
old pilot's checker outcome remains useful with its recorded attestation limit.
