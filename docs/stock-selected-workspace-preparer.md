# Inactive original stock selected-workspace preparer

This local source slice depends on the stock contracts, measurement adapter and
supervisor. It changes no active reader, image recipe, workflow, admission, State,
task, Source capability or runtime permission. The separate hosted-Python test
fixture correction is a test-only prerequisite. No historical row is qualified.

`prepare_stock_workspace.py` reads exact local Git objects, not an existing
working tree's claimed hashes. Benchmark commit/tree selection is the closed
four-configuration set used by the five stock matrix rows (twelve pending items):
208b6b22/435rc3 private;85a88c37/435rc3 public;8955681b/435stable public/private;
8955681b/436rc2 private. Visibility/Source authority is still independently required.
No submitter repository or secret is fetched by this module. Public dependency
source/build-cache preparation is separate from submitter Source access.

The Git reader disables replacement objects, hooks, filesystem monitors, global
configuration and network protocols. It verifies the exact commit/tree,
regular-file modes, blob identity and bytes. Export is exclusive and fresh,
preserves original files/modes and carries no credential-bearing Git metadata.
For multi-toolchain snapshots it executes the exact Git-bound original
prepare_toolchain.py --apply, then verifies all selected configuration bytes.
Committed generated files remain input evidence only, never generation proof.

## Explicit selected invocation contract clarification

The existing configuration-lock1 schema retains its exact constant command
`["lake","exe","lean-eval","generate"]`. Its new description makes the
previously unstated interpretation explicit: that field names the original
generator entrypoint. This inactive preparer resolves exactly
`[*command,"--problem",sole_bound_problem_id]` from the validated one-problem
revision map. Zero/multiple maps, noncanonical names/revisions and arbitrary
caller argv/flags refuse. The complete resolved original argv is recorded in
preparation evidence and checked at context handoff. No generic argument
permission or active consumer/admission follows from this clarification.

The genuine original CLI supports --problem. Selected generation intentionally
does not perform the NONE branch's full-catalog inventory check, unknown-directory
synchronization or index rewrite. Before it, the preparer executes original full
validate-manifest (including validateManifestAgainstInventory) and
validate-generated-catalog against the exact original Git snapshot. The full
semantic guard runs the genuine original eval_inventory; no structural-only or
selected-inventory substitute is accepted. Before it, the preparer derives ALL
original modules in original manifest filename/first-occurrence order and builds
them in fixed batches of at most four original `lake build <module>` commands.
Only successful real child exits plus original module artifacts allow the
original supported `validate-manifest --assume-modules-built` invocation. That
flag skips rebuilding only; every original module is still imported and the
full semantic inventory is compared. No synthetic inventory is supplied.

One monotonic deadline of at most1200 seconds covers plan loading, the original
structural precheck, ALL batches and the final full validator. It is never reset
per batch. The selected generator still has its independent at-most300-second
bound, and runtime M/T are unchanged. Any partial failure, deadline or cleanup
failure leaves generation/context unproved. A four-worker limit and
LEAN_NUM_THREADS=1 hint apply to these trusted public builds. Each build child
also inherits kernel CPU-time and at-most32GiB virtual-address-space limits;
stricter inherited limits are preserved. The address limit is not physical RAM
or aggregate VM memory enforcement. Actual provider resource qualification
remains separate.

All actual preparation subprocess sites share scoped ownership: build/generator
commands, short Git/selector/version commands and captured Lake environment
probes. Linux pidfds and WNOWAIT retain every owned leader through the last group
kill, including leaders that already exited. Success, nonzero exit, deadline and
termination signals all stop and reap owned groups BEFORE returning or accepting
the original real leader exit status. A temporary process-local child-subreaper
setting makes orphan descendants in those groups reapable; the previous setting
is restored on every path. Every group is reserved before any reaping. Only
reserved groups are waited/signalled; unrelated live or exited children are not
consumed. There is no waitpid(-1) or broad process scan/kill.

This assumes a dedicated synchronous preparation process with default SIGCHLD,
not a shared threaded server or external child reaper. Incompatible automatic
reaping is refused before launch, because it could release leader identity.
Cancellation is recorded while teardown runs, and handlers/settings are restored
before cancellation propagates. Captured stdout is drained without blocking,
limited to the existing16MiB bound, and requires EOF after owned writers stop;
existing smaller checks (such as8192-byte environment probes) remain in force.
Original argv, timeout caps and successful output bytes are retained. This
trusted-public-build ownership does not replace untrusted Source PID-namespace
containment, physical/aggregate provider resource qualification, provider
destruction or job/scratch cleanup qualification. Selected source/module/manifest/revision and all
global catalog inputs are bound by that immutable tree. The loader ignores only
the original exact `.DS_Store` entry, rejects other stray files/directories, and
conserves first-occurrence module order. Canonical dotted ASCII module operands
are additionally required before process launch; all296 original modules in all
four frozen configurations satisfy that grammar. No configuration is widened. The full semantic guard
is preserved separately; selected generation still does not rewrite the entire
generated catalog or index.

## Original build, closure and C

The owned generation path exports exact original public benchmark code, creates
fresh dependencies from the selected manifest's exact Git commits, invokes the

in that selected root context, builds the
original lean-eval/extract_theorem/eval_inventory targets, verifies original
inputs unchanged, removes only the bound problem's retained generated directory,
and invokes that resolved original command within a bounded timeout. No supplied
build receipt, synthetic started flag, patched compiler/Lake, or retained
workspace can replace actual command success. Failures produce no successful
generation observation. Trusted builder timeout cleanup concerns its owned
process group; submitted Source containment remains the separate namespace
supervisor's responsibility.

Original stock release/runtime authentication is an independent prerequisite;
Lean --version and observed launcher hashes do not qualify the runtime closure.
This implementation imports no arbitrary build-cache receipt. The original
`lake exe cache get` helper derives public artifact keys from its pinned source;

No emitted shell text is evaluated, arbitrary endpoints are not supplied, and
all cache/control temporary files stay under the owned builder home.
There is no supplied cached-workspace/hash shortcut. A missing cache/tooling or
a cold build that exceeds the bound leaves generation unproved; a timeout
extension or fake generation receipt does not repair it.

The selected generated workspace retains every original trusted file, including
README.md, holes.json, optional ChallengeDeps.lean and the unchanged WorkspaceTest.

primed outside the original comparator sandbox. Fresh owned dependency Git

Before freezing the full prepared cache/closure, the preparer captures the actual
original driver environment: invoking PATH, filtered comparator-inherited PATH,

Per-problem configuration is represented within the existing schema by exactly

## Source/context handoff and limits

The public Git overlay validates the complete request/configuration against
actual benchmark and authority Git objects, exact Source commit and a
credential-free public-route origin URL. URL consistency does not prove remote
visibility, ownership or historical classification; those remain required
independent authorities. It uses the existing original detect_matches/pristine-skip/
duplicate and Source overlay helpers. Only Submission.lean and Submission/**/*.lean
enter the workspace. Submitter config/Challenge/Solution replacements are never
copied. The benchmark closure must remain unchanged after overlay.

Generation returns a private in-process owned result. Its copied observation is
for review/output, not a transferable authority or accepted JSON receipt.
Context handoff refuses serialized/caller-supplied observations; it accepts only
the owned generation result within this trusted preparation process and rechecks
its original identities, current tool bytes, complete prepared manifest and
validated request. This API distinction does not protect against arbitrary code
already executing within the trusted preparer, and does not grant task authority.

Context handoff verifies the stock Check.lean bytes against the exact published
Lean Git commit and derives original exporter ordering, including conditional
Quot builtins and definition names. Tool hashes are checked by the existing
factory against profile3; P/M/T, problem/revision, original authority, environment,
prepared closure and literal Source commitment are retained. The all-zero
generation/start values are explicit template slots; the supervisor alone writes
fresh generation and actual monotonic start before go. This module never invokes
lake test, the checker, the supervisor or an active task consumer automatically.

Private/archive Source remains unsupported here until the existing authenticated
decryption/Source boundary is integrated and reviewed. A caller-provided plaintext
digest or receipt does not prove archived Source, and no replacement private-key
or ciphertext-purpose authority is invented. Closed selection covers the four
configurations used by all five rows; observed selected generation currently
covers only the separately reported stock208 component. This public overlay does
not claim the private rows executable.

Tests use real pinned benchmark Git objects and controlled owned Source/authority
Git repositories, not real submitter Source. Original stock generation observation
is reported separately from schema/fixture checks. Image/runtime/dependency
qualification, historical classification, Source/archive/State authority,
authorized M and provider/job/scratch cleanup remain independent gates.
